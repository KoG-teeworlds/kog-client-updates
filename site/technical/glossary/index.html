The KoG client is a reference implementation. It exists to demonstrate and test new features that need client integration, such as new network messages and the KoG login. You do not need it to play on KoG: the normal DDNet and Teeworlds clients are fully supported. Builds are for testing and may change or break. Just want to play? →

Glossary Built

Short explanations of the words used in these pages, in alphabetical order.

Attestation
A signed statement, kept by GitHub, of which workflow and commit built a file. Checked with gh attestation verify. See verify.
Canary
The channel built from every push to main. For testers; signed by a CI key only.
Channel
One of stable, canary and dev: a stream of builds with its own manifest, keys and validity time. Chosen by you, never by the network.
CI key
A signing key used by the project's automation. Each channel has two, a and b, and the client trusts both.
Device key
An Ed25519 key pair made on your computer at login. The private half stays in the key store; the public half is registered on your account. See login.
Ed25519
The signature scheme used for manifests and for the device key. The client uses the Monocypher library for it.
Expiry (expires)
The time after which a manifest is refused. It limits how long a stale or replayed manifest is useful.
Halt
A signed manifest with halted: true that tells clients not to update. See release signing.
Hardware key
A security key (FIDO2) that makes signatures without exporting its private key, and needs a touch. The owner's signature B for stable.
kogsign
A small program in the client repository that verifies a manifest signature. See verify.
Loopback listener
A short-lived listener on 127.0.0.1 that receives the redirect of your browser at the end of the login.
Manifest
The signed file update.json that lists the files of a version with their hashes. See update channel.
OAuth 2.0 authorization code flow
The login method in which you type your password only in the browser, and the client receives a short-lived code.
PKCE
Proof Key for Code Exchange (RFC 7636). A random secret made by the client, whose hash is sent first and itself later, so a stolen code is useless to anyone else.
Rollout
The share of installs (rollout_percent) that are offered an update, chosen with a random number that stays on your computer.
Rollback protection
The set of checks that stop an older version from replacing a newer one by trickery: sequence, expiry, version rules and bad-version memory.
Sequence
A number in the manifest that rises with every manifest of a channel.
Stable
The channel for released versions, which will need two signatures. It does not exist yet.
State (state)
A random value the client puts in the login URL and expects back unchanged in the callback.
