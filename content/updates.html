Updates and channels

How the client updates itself, and why a taken-over download host cannot push a bad update.

The updater is not switched on in the builds made so far. This page describes the design that is in the source.

How an update works

  • Linux (64-bit) and Windows (64-bit) can update inside the app. On macOS you download new versions by hand.
  • At start the client downloads two small files, update.json and update.json.sig, from client.kog.tw. The setting is kog_check_updates and it is on by default. Nothing is installed without asking.
  • The client trusts only an Ed25519 public key compiled into it: not the host, not TLS, not GitHub. A manifest without a valid signature is ignored.
  • After the signature it checks the format, the version number and the validity window (at most 90 days). Expired manifests are refused. A manifest with a lower sequence number than the last one seen is refused, so an old manifest cannot be replayed. The new version must be higher than the running one.
  • Every file is checked against its SHA-256 and size. Downloads may only come from github.com/KoG-teeworlds/kog-client/releases/download/ or client.kog.tw.
  • Replaced files are backed up and put back if anything fails.
  • If GitHub or client.kog.tw cannot be reached, the client keeps running the version you have.

Channels Planned

Only the stable channel is described in the committed update documentation. Canary and dev are in progress.

ChannelWhat it isWho it is for
StableTagged releases from the main branchEveryone
CanaryBuilds of main after each mergeTesters
DevBuilds of the dev branchTesters and developers
  • Each channel has its own signing keys, and the client checks the channel name inside the signed manifest. A problem in a test channel cannot sign a stable release.
  • You choose a channel in the client settings, never through a server message or a link. Going back to stable from a newer channel will be an explicit step that you confirm, because it installs an older version.
  • Canary and dev builds can break. They may need a clean reinstall of the stable version.

When an update fails

If something goes wrong while files are being replaced, the old files are put back. Planned An automatic rollback when a new version fails to start twice in a row.

Who can publish an update

A release is signed in the public kog-client-updates repository by a job that needs the maintainer's approval. The private signing key is stored as a write-only secret there and is not in any repository or log. The full design and threat model are in the update channel document. You can check a manifest yourself: see Verify your download.
