KoG Client

A reference client for King of Gores, built to try out features that need the client. A fork of TClient, which is a fork of DDNet.

Disclaimer

The KoG client is a reference implementation. It exists to demonstrate and test new features that need client integration, such as new network messages and the KoG login.

You do not need it to play on KoG: the normal DDNet and Teeworlds clients are fully supported.

Builds are for testing and may change or break. It is maintained by volunteers on a best-effort basis, with no warranty and no support guarantee. Use at your own risk.

How to verify your download

Download only from the buttons above or from the GitHub releases page. Then check that the file is the one the project built:

  1. SHA-256. Each card above shows the hash from the signed release information, with a command to compare it. Or run sha256sum FILE (Linux), shasum -a 256 FILE (macOS) or Get-FileHash FILE (Windows PowerShell) and compare the result with the card.
  2. Build attestation. GitHub signs a statement of which workflow and commit built each file. Check it with gh attestation verify FILE -R KoG-teeworlds/kog-client, or see the attestations of the repository.
  3. Signed manifest. The hashes come from https://client.kog.tw/CHANNEL/update.json and its signature update.json.sig. The public keys of each channel are compiled into the client, in kog_update_pubkey.h. The stable channel has no real key yet.

Step-by-step guide. If a check fails, do not run the file and tell us privately.

What is this?

A DDNet-based client with the KoG-specific parts kept in separate files, so upstream changes can still be merged. Its job is to be a working example for features that need both a client and a server, for instance new network messages announced with capabilities, and logging in to your KoG account in the browser instead of typing a password into the game.

  • Based on TClient 10.9.0 and DDNet 20.1.
  • Removed from TClient: the ChaiScript scripting engine, chat translation (it sent chat to a third-party service) and a bundled Steam library. No contact with TClient's servers.
  • No telemetry, analytics or crash uploads. Every connection the client makes is listed.
  • Update checks verify an Ed25519 signature on the manifest and every file's SHA-256. How updates work.

Known limits

  • No stable release yet. Only canary builds exist, and they can break.
  • Not code-signed. Windows SmartScreen and macOS Gatekeeper warn on first start. The macOS build is not notarised.
  • No in-app update yet. The updater is written but not switched on: download new versions by hand.
  • The KoG login is only in canary and dev builds and is off unless cl_kog_login is on.
  • Platforms: 64-bit x86 Windows and Linux, and a macOS disk image. No Android or iOS.
  • Still named DDNet inside: the program in the package is DDNet and it shares its data folder and settings with an installed DDNet or TClient. Back up that folder first.
  • Inherited assets such as fonts and artwork from TClient still need a licence check before a first release. The notice file lists them.
